# 采集截图、模板和操作流程

BJX 沿用「截图 → 识别当前界面 → 执行动作 → 再截图确认」的流程。可以参考[三月七小助手视频](https://www.bilibili.com/video/BV1YP4F69EgA/)介绍的方法，按钮、文字和界面状态必须采集剑网3无界自己的实机画面。视频标题与简介已核对，未逐帧核对视频内容。

## 先做截图合集

需要按任务和状态整理截图。现有任务主要使用 OCR，`resource/image/` 目前只有占位文件；没有模板图片并不等于没有识别逻辑，但仍缺少经过整理、能复测各分支的画面样本。

先检查 `debug/screencap/`、`debug/on_error/` 和 `debug/vision/` 中已有的画面。前两者有完整截图，后者也可能包含识别框、裁图或缩放后的图片，不能全部直接当模板。旧版 1280×720 截图不能冒充当前 1920×1080 基准画面。

采集约定：

- 窗口模式，**游戏客户区** 1920×1080，界面缩放 100%。桌面分辨率和带标题栏的窗口尺寸不是客户区尺寸。
- 优先保存 MaaFramework 实际拿到的 PNG 原图；保留完整画面，另存按钮裁图。不要只留拼图、压缩后的聊天图片或带标注的图。
- 同一个按钮的可点击、灰色、已领取状态分别保存；加载中、遮挡和识别失败也单独保存。
- 每种状态先收 1～3 张；有动画、不同背景或偶发误识别时再加样本。记录游戏版本和采集日期。
- 原始截图先放本机 `debug/captures/<任务>/<状态>/`。核对后，只把需要的按钮模板放进 `resource/image/`；带角色名等信息的原始截图不用整包提交。
- 每张图记录：当前状态、识别依据、允许的动作、动作后的目标状态、失败时如何退出。文字识别记录原文和 ROI `[x, y, width, height]`，坐标相对游戏客户区。

## 优先补吃鸡

| 状态 | 至少要保留的内容 | 用途 |
| --- | --- | --- |
| 主界面／沧海集 | 顶部固定入口、地图名 | 确认能从哪里打开绝境 |
| 绝境五人页 | 模式名称、单人入口、底部按钮 | 防止在五人页点到个人匹配 |
| 绝境单人页 | 单人模式、龙门绝境、个人匹配 | 确认模式已切换 |
| 飞沙令大于零／为零 | 「本周还可获得飞沙令」及右侧完整数字 | 校准数字 ROI，验证停止条件 |
| 排队中 | 取消匹配、预计排队 | 排队期间不当作进局，不取消匹配 |
| 加载中／黑屏／过场 | 完整画面 | 避免把文字暂时消失当作已进局 |
| 局内 | 稳定的局内 HUD、地图或阶段标志 | 用正向依据确认进局，不能仅凭排队文字消失 |
| 局内阵亡 | 阵亡、观战等实际界面 | 与主城的回城复活区别处理 |
| 结算页 | 下一步、传出战场、倒计时 | 确认这一局结束 |
| 回到沧海集 | 已见退出页、加载完成后的地图名和主界面 | 先确认本局退出再允许打开下一次匹配；单独看到主城不重排 |
| 错误／遮挡 | 活动弹窗、断线、匹配失败等实际出现的画面 | 关闭已知遮挡或截图停止 |

优先留一段从打开绝境、切单人、排队、进局到结算返回的完整录屏，用来对齐截图的先后和等待时间。录屏辅助解释过程，识别样本仍保留原始截图。

## 路径指界面流程，暂不录跑图路线

当前任务需要的是界面之间如何到达的操作流程，例如：

`主界面 → 绝境面板 → 单人页 → 排队 → 加载 → 局内 → 结算 → 沧海集`

给每一步补上识别依据、动作、成功后的状态、超时去向和退出方式。停止是每一步都要验证的分支，不能依赖流程最后一个节点才清理。

吃鸡提交一次匹配后，只能在本局流程里等待和处理局内按键。重新匹配的前提是先看到退出／结算页，再等待加载并确认返回主城。原始截图测试之外，还要按时间顺序重放完整画面变化，验证黑屏、看起来像主城等中间画面不会把流程带回匹配入口。

当前吃鸡不寻路、不捡物资、不躲圈；其他点击型日常的移动交给游戏自己的「前往」。按 [ADR 0002](adr/0002-delegate-to-ingame-automation.md)，目前无需收集地图坐标或录制角色移动路线。只有后续明确增加没有游戏内自动寻路的野外任务，才另行定义地图定位、起终点和路线素材。

## 制作模板

1. 游戏保持窗口模式、1920×1080、界面缩放 100%、无界默认界面。
2. 用 MXU 或 MaaDebugger 截下当前画面，裁出目标按钮或图标，边缘留几个像素。
3. 图片放进 `resource/image/`，文件名和节点里的 `template` 一致，例如 `resource/image/mail/entry.png`。
4. 节点改成 `TemplateMatch`，阈值先用 `0.8`。点击动作写 `Click`，目标用识别框本身。
5. 文字比图标更稳的地方用 `OCR`，`expected` 写界面上的原文，区域尽量缩小。
6. 同一按钮在弹窗和主界面都会出现时，用界面上另一块稳定文字或图标先确认屏幕，再点。

占位节点里的「待校准」句子是故意匹配不到的。换上真实文字或模板之前，不要把 `action` 改成 `Click`。
