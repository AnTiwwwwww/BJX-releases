# 架构

BJX 是一套 MaaFramework 资源，不是另一套识别运行时。Mirror酱项目列表里，日常助手大多是这个形态。

## 同类项目怎么分

| 家族 | 代表 | 和 BJX 的关系 |
| --- | --- | --- |
| MaaFramework | MAA、MaaYYs、梦幻西游手游小助手、M9A、战双与尘白的 MAA 派生 | 直接沿用。流水线、Win32 控制器、通用界面都是现成的 |
| BetterGI | BetterGI、BetterNTE | 大世界寻路和脚本仓库的做法以后再借。无界日常多数有「前往」，第一期不自己走路 |
| ok-script | 鸣潮 ok-ww、绝区零一条龙、ok-gi | 另一套 Python 运行时，后台操作更激进。BJX 不采用 |
| 通用壳 | MXU、MFAAvalonia、MFW-PyQt6 | 不自写界面。`interface.json` 交给 MXU 或 MFAAvalonia |

梦幻西游手游小助手和痒痒鼠小助手更接近「多日常、对话、进副本」。它们的仓库保存资源、流水线和少量自定义逻辑，运行库和通用界面随发布包提供，不进源码。BJX 同样处理。

BetterGI 的难处是小地图定位和路径文件。无界自己会寻路，所以地图匹配放到有「前往」覆盖不到的野外步骤之后。

## 目录

```
interface.json          通用界面读的项目声明
resource/pipeline/      任务节点
resource/image/         模板图，按界面区域分子目录
resource/model/         需要自训模型时再放
scripts/                单人副本脚本。签到和吃鸡不放这里
docs/                   取舍和采集约定
```

节点只写四件事：在哪一块里找、用文字还是模板、找到后做什么、成功或超时去哪。维护日换图和改节点，不改运行时。

## 控制器

电脑端 Win32，识别坐标按 1920×1080、100% 界面缩放采集。MXU 不读 `display_raw`，连接时会把短边缩到 720，所以控制器同时写了 `display_short_side: 1080`。1920×1080 的窗口因此保持原尺寸。命令行 MaaPiCli 认 `display_raw`，本来就是原尺寸。

默认截图是 `FramePool`，键鼠是 `Seize`。窗口类名限定 `KGWin32App`，标题仍匹配剑网3，避免把标题里带剑网3的其他程序绑进来。`Seize` 会使用前台输入，点击时鼠标会进游戏窗口。无界是独立绘制的客户端，`PrintWindow` 经常拿到黑图，所以不把它当作默认值。

远程软件在操控端捕获鼠标，是另一层状态。2026-11-04 的 UU 排查中，BJX 退出后仍无法从屏幕边缘切出，操控端按 Ctrl+Alt+Enter 恢复。恢复步骤见 [README](../README.md#网易-uu-远程的鼠标无法切出)。控制器自身的输入自检不能证明操控端的跨屏切换正常；后台消息输入也需通过组合键、鼠标点击和整轮任务验证后才能替换默认方式。

## 现在故意不点

点击目标是画面上的文字。已知弹窗的关闭词还是占位，实机看到弹窗后再补进 `点已知关闭`。签到和单人吃鸡刷币的按钮文字来自公开说明，对不上就改字。单人副本的文字由导入的脚本自己写。

每一项从主界面开始。认不出的画面留下截图并跳过该项。死亡或卡住则按重跑上限重跑这一项。回不到主界面，或遇到登录验证，整次运行结束。

## 多角色

切换账号和切换角色是两项勾选，默认不勾。一次运行里它们排在日常前面：先点客户端已经显示的账号名，再点角色名进入世界，然后做后面勾上的日常。当前切换流程不读取本地账号表，不输入密码。出现登录验证或选服页就截图并停掉这一项。多名角色排队、把同一批日常重复做完，仍留在后面。

`accounts.csv` 是本机手工维护的账号表，一行一个角色，包含账号、密码、区服、角色名称和备注；同一账号可有多行。它已被 Git 忽略，仓库只保存空白模板 `accounts.example.csv`。后续换号登录可读取此表，当前尚未接入自动登录。
