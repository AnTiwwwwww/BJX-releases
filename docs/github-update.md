# GitHub 联网更新

BJX 从 `0.4.2-beta.1` 开始使用定制 MXU `2.8.0-bjx.1`，直接读取 [BJX Releases](https://github.com/AnTiwwwwww/BJX-releases/releases)。不需要申请项目接入、RID、CDK 或 GitHub Token。源码和构建方法见 [MXU 补丁](../integrations/mxu/README.md)。

## 用户如何更新

`0.4.1-beta.1` 及更早版本需要手动换包一次：停止任务并关闭 BJX，把新版整包完整解压到新目录，将旧目录的 `config/`、`accounts.csv` 和自有 `*.local.*` 通知配置复制过去。保留旧目录，确认任务选项后再运行。

首次换包后，启动时自动检查；也可在「设置 → GitHub 更新」点击检查更新。发现新版会显示更新说明并下载。全新配置默认选择内测频道；沿用旧 `config/` 时保留原频道，想接收 beta 版本请选「内测」。稳定频道只接收正式版。

下载可以在任务运行中完成，但任务队列运行或定时等待时不安装。所有任务停止后沿用 MXU 的自动安装、重启流程；手动点击安装也要通过任务状态检查。安装期间底层拒绝新任务启动。不要在仍要使用电脑时依赖“下载完不会自动重启”的假设。

只选与版本号完全一致的 Windows x64 BJX 整包，忽略源码 ZIP 和其他架构。下载完成后核对 SHA-256，安装前再次核对；优先使用 GitHub 返回的资产 digest，缺少时读取同一 Release 的 `.sha256`。无校验值或校验失败不会安装。校验防止包损坏或被替换，不等同于独立代码签名。

整包会替换程序、资源和工具，删除被新版移除的旧任务文件。`config/`、`accounts.csv`、账号表备份、`*.local.*`、`cache/`、`debug/` 和 `logs/` 受保护。用户自行修改的 `resource/` 或 `tools/` 不属于个人配置，升级前自行保存。

## 网络或安装出错

GitHub 无法访问、API 限流或下载失败时，可以继续使用现有版本，稍后重试。设置里可填写自己可用的 HTTP/SOCKS5 代理；BJX 不提供公共代理。没有内置开发者凭证。

安装失败会显示错误，必要时保留 MXU 的新版本目录恢复方式。这一版没有承诺完整事务回滚；也可关闭 BJX 后手动下载整包到新目录，迁移自己的配置。不要从陌生来源下载安装包。

## 维护与验收

维护者只需要维护 GitHub Release：修改界面版本与更新说明，同步任务路线图，经过 Windows CI 验证后发布。程序 ZIP 命名为 `BJX-win-x86_64-v<版本>.zip`，另附 `.sha256`、BJX 源码及定制 MXU 完整对应源码。完整构建步骤见 [发布说明](publishing.md)。

自动验证包括版本/频道/错误路径、真实安装函数的任务状态保护、Rust 哈希与文件替换、整包隐私和配置保留。自动验证不替代用户电脑上一次真实的「发现下一版 → 下载 → 停止任务 → 安装重启」验收，记录见 [升级验收](update-validation.md)。

新号主城问题仍是“故障画面回放通过，实机待确认”。手动关闭新手引导后恢复不能视作备用识别已在实机验证；设置开关路径待补充。
