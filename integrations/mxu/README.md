# BJX 的 MXU 定制补丁

本目录固定上游 MXU 2.8.0 的提交，并保存 BJX 的 GitHub Releases 更新及启动预任务补丁。`build.json` 记录上游、补丁校验值和定制运行时版本；`github-update.patch` 包含对应源码与测试。

补丁提供公开 GitHub 更新检查、0.x 内测版本比较、精确 Windows x64 整包匹配、下载和安装前 SHA-256 校验，以及安装与任务启动互斥。无 RID 时不显示 CDK 输入，默认内测频道；稳定频道只接收正式发布。用户数据不随整包覆盖。

`2.8.0-bjx.2` 增加连接窗口前的启动预任务保护：任何预任务非零退出或启动失败都会中止本次运行；点击停止会终止启动助手本身，不结束它已打开的游戏。仅勾选预任务时，完成后直接成功返回，不连接窗口、不加载资源。预任务后继续执行普通任务时重新发现并连接窗口；旧标题变化仅在新窗口唯一时自动匹配，多个候选时停止。预任务等待期间与更新安装互斥，参数值不写入日志。

启动预任务按 `interface.json` 中的声明顺序执行，始终早于普通任务（包括普通「定时开始」），不受卡片排序影响。密码应由 Agent 在内存读取本机账号表，不应作为预任务命令行参数传递。

`2.8.0-bjx.3` 增加可选协议扩展 `startup_guard: { exec, args, option, task_option, entry }`。声明后，工具栏、仪表盘、快捷键和定时启动统一在全部预任务、前置程序及 Controller 连接之前调用检查助手。此检查自动执行，无需添加或勾选任务卡片；没有此扩展的项目保留原行为。检查复用预任务的停止控制、输出面板及后端更新互斥，停止只终止检查助手。退出码 20 显示服务器维护、本次跳过；21 显示状态未知、本次跳过；22 按取消处理；其他非零或启动异常同样阻止后续任务和结束后操作。助手标准输出保留邮件发送结果，命令行参数值不写入 MXU 日志。

助手收到的最后一个参数为 JSON：`{ run_id, options, tasks: [{ name, entry, options }] }`。`run_id` 是每次启动新建的 36 字符 UUID，在本轮全部检查中保持一致；选项按 PI 默认值与当前值序列化，再严格限制到 `option`、`task_option` 白名单，并移除标记为密码的输入字段。任务数组包含本轮启用且兼容的预任务（声明顺序），随后为普通任务的实际队列顺序；同名任务通过所选任务的唯一 ID 关联数组位置。BJX 的全服检查将两个白名单设为空数组，不向检查助手传账号表行号、区服或凭据。

普通任务的原入口由 `startup_guard.entry` 包装，在该节点最后追加 pipeline override：`custom_action_param` 为相同快照加 `task_index`，`next` 为该任务原入口。因此每个普通任务开始前都会复查，普通「定时开始」等待结束后的下一项也有检查。检查节点由项目资源定义，失败时须主动停止 Tasker 队列；是否为关闭或诊断等免联网任务，由项目助手根据任务快照判断。此扩展只覆盖 MXU 的统一前端启动入口，直接调用底层 Maa API 的集成需要自行提供同等检查。

当 Agent 通过 `MaaTaskerPostStop` 停止整次运行时，MXU 在原生任务回调中检查 `stopping()`，将中断产生的成功回调按失败处理，并结束被清除的剩余队列，避免登录失败显示成功或留下等待中的后续任务。普通节点失败后通过 `on_error` 恢复的流程仍可成功；这里只处理整队列停止，不按 BJX 任务名判断。

在 Windows x64 安装 Node.js 22、pnpm 10.28.0、Rust stable 和 Visual Studio C++ 构建工具后，在 BJX 根目录运行 `./tools/build-mxu.ps1`。构建使用上游锁文件；失败不会生成可供整包使用的构建回执。发布工作流负责执行前端、Rust、运行门禁和整包检查。

MXU 及本补丁按 AGPL-3.0 分发，许可见 `licenses/MXU-AGPL-3.0.txt`。每次 Release 附带与 `build.json` 版本一致的 `MXU-source-v<runtime_version>.zip` 及 SHA-256，包含完整对应源码、锁文件和测试；BJX 源码包提供本补丁与构建脚本。BJX 自有资源的 MIT 许可不改变第三方代码许可。

这里的补丁是 BJX 自行维护的改动，不代表 MXU 上游已经接受这些修改。升级上游版本时必须重新审查并执行测试。
